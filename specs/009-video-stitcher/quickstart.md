# Quickstart: Validating Video Stitcher

This is a manual/automated validation guide for Video Stitcher once implemented per [plan.md](./plan.md), [data-model.md](./data-model.md), and [contracts/video_stitcher_contract.md](./contracts/video_stitcher_contract.md). It does not contain implementation code -- see `tasks.md` (generated by `/speckit-tasks`) for build steps.

## Prerequisites

- Python 3.11+ environment with project dependencies installed (`pip install -r requirements-dev.txt`).
- `ffmpeg`/`ffprobe` installed and on `PATH` (`docs/DEPENDENCIES.md`) -- run `cvip doctor` or `ffmpeg -version` to confirm before starting.
- **Unlike every module since Module 4a, this feature needs real (if tiny) video fixtures**, not purely synthetic in-memory objects (research.md Decision 9) -- `tests/fixtures/video_stitcher/generate_fixtures.py` produces a few seconds of test-pattern footage via `ffmpeg` for use in the scenarios below.
- A hand-built `ClipPlan` (Module 8's own output type, `cvip.clips.models`) referencing one of the generated fixture videos and a set of `PlannedClip` time ranges within its duration.

## Scenario 1 -- Get a single playable highlight video (User Story 1)

1. Construct a `ClipPlan` with three ordered, non-overlapping `PlannedClip`s against a fixture video, and an output path in a scratch directory. Call `stitch_video()` and run it to completion.
2. Expected: `result.output_path` exists, is a valid MP4, and its playable content is the three clips' footage, in order (FR-002, Acceptance Scenario US1-1).
3. Construct a `ClipPlan` with a single `PlannedClip`. Expected: `result.total_duration_seconds` equals that clip's `clip_end_seconds - clip_start_seconds`, within the keyframe-snapping tolerance (Acceptance Scenario US1-2).
4. Re-run `stitch_video()` with the same request (same output path) immediately after a successful run. Expected: `.run()` raises `VideoStitchingError` with `OUTPUT_ALREADY_EXISTS`, and the original output file is untouched (Acceptance Scenario US1-3).

## Scenario 2 -- Highlight video retains original broadcast quality (User Story 2)

1. Inspect the fixture video's own resolution/frame rate/codec via `ffprobe`. Run `stitch_video()` against a `ClipPlan` referencing it.
2. Expected: the output file's resolution/frame rate/codec (via `ffprobe` on the output) exactly match the source's own (FR-004, Acceptance Scenario US2-1).
3. Inspect the internal `StitchEvidence.ffmpeg_invocations` for each segment extraction and the concatenation step. Expected: every command includes `-c copy`, never a re-encode flag (FR-003, Acceptance Scenario US2-2).

## Scenario 3 -- Fail clearly instead of producing a broken video (User Story 3)

1. Temporarily rename/hide `ffmpeg` from `PATH` (or mock `shutil.which` to return `None`). Call `stitch_video()`. Expected: `.run()` raises `VideoStitchingError` with `MISSING_FFMPEG`, and no output file is created (FR-008, Acceptance Scenario US3-1).
2. Construct a `ClipPlan` referencing a source video path that doesn't exist. Expected: `.run()` raises `VideoStitchingError` with `SOURCE_VIDEO_UNAVAILABLE`, and no output file is created (FR-009, Acceptance Scenario US3-2).
3. Construct a `ClipPlan` with zero clips. Expected: `.run()` raises `VideoStitchingError` with `EMPTY_CLIP_PLAN`, and no output file is created (FR-006, Acceptance Scenario US3-3).
4. Simulate a mid-stitch failure (e.g., a fixture video that becomes unreadable partway through, or a mocked `ffmpeg` subprocess call that exits non-zero on the second segment). Expected: `.run()` raises `VideoStitchingError` with `STITCH_OPERATION_FAILED`, and no partial output file or temp directory remains (FR-010, Acceptance Scenario US3-4).
5. Simulate FFmpeg reporting success but producing an invalid file (e.g., mock the concatenation step to exit 0 while writing a zero-byte file). Expected: Output Validation catches this, `.run()` raises `VideoStitchingError` with `STITCH_OPERATION_FAILED`, and the invalid output file is removed (FR-011, Acceptance Scenario US3-5).

## Scenario 4 -- Traceability, determinism, and diagnostics

1. Run `stitch_video()` and inspect `result.source_clip_ids`/`result.source_event_ids`. Expected: they match the stitched `ClipPlan`'s own `PlannedClip.clip_id`/`source_event_ids` values (FR-017).
2. Inspect the internal `StitchEvidence` after a run. Expected: it records every FFmpeg invocation's command, the extracted segment paths, the concatenation order, and every cleanup action taken (FR-018).
3. Run the same `ClipPlan` twice, against two different output paths. Expected: both output files have identical duration and identical stream parameters (resolution/frame rate/codec) -- but are not required to be byte-for-byte identical (FR-014, SC-006).
4. After both runs above, inspect the OS temp directory. Expected: zero leftover temporary artifacts from either run (FR-015, SC-008).
5. Construct a `ClipPlan` with a few dozen clips against a longer fixture video and run `stitch_video()`, recording elapsed time. Expected: elapsed time is well within the platform's 2-minute `generate` budget (SC-005).

## Pass/fail

All four scenarios must pass exactly as described for this feature to be considered validated end-to-end. Any deviation should be filed against the relevant functional requirement or success criterion in [spec.md](./spec.md) rather than patched ad hoc.
